# Rust/rextendr installed-size optimization

## Scope

This change optimizes only the disposable R/rextendr prototype generated by
`prototypes/rust-rextendr/prepare-r-package.R`. It does not change the
production R package, the shared-core API, or the standalone CLI build.

The R package has its own generated Cargo manifest under
`.ci-r-package/src/rust`. Consequently, the `[profile.release]` section in
`tools/corrplot-ng/Cargo.toml` is not inherited by the R package. The
generator now writes a size-oriented release profile into that generated
manifest:

```toml
[profile.release]
opt-level = "z"
lto = true
codegen-units = 1
strip = "debuginfo"
```

This asks rustc to optimize for binary size, enable link-time optimization,
use one codegen unit, and remove debug information while retaining normal
symbol information needed by native linking and diagnostics.

## Dependency audit

The R prototype's tracked Cargo manifest declares only:

- `extendr-api = 0.9.0`
- the local `corrplot-core` path dependency

The standalone CLI is a separate Cargo package under
`tools/corrplot-ng`; it is not a dependency of the R package. The R package
does not build the CLI executable. CI prints the normal Cargo dependency tree
for the generated R package so future changes to its dependency graph are
visible in the workflow logs.

The core crate currently exports validation plus renderer-neutral output and
raster modules. The R adapter directly uses only `validate_matrix` and
`MatrixKind`. Rust's linker may already discard unreachable code, so
introducing Cargo features or splitting the core crate is not justified
without symbol-level evidence. This PR deliberately does not change the shared
core's public API or create a second R-specific implementation.

## Measurements

The latest recorded pre-change measurement (Ubuntu 24.04 / R 4.6.2, 2026-10-31)
was:

| Measurement | Before |
| --- | ---: |
| Installed package | 6.0 MB |
| Installed `libs` directory | 5.9 MB |
| Source tarball | 1,314,220 bytes |

The offline-package workflow now reports, on each Linux, macOS, and Windows
run:

- total installed package bytes;
- installed native library bytes and per-file sizes;
- Rust static-library build artifact bytes;
- the generated R package's normal dependency tree.

The workflow now builds and installs both the unmodified Cargo release
defaults and the size-oriented profile on the same runner, using separate
Cargo target directories and R library directories. These same-run results
are the authoritative comparison for each OS. The historical 6.0 MB figure
is useful context but is not a substitute for this controlled baseline. Do
not claim a size reduction until the new workflow has completed and the
before/after measurements are comparable.

## Follow-up decision rule

If the optimized build remains above the 5 MB rextendr caution, inspect the
native library with platform-appropriate symbol/section tools before
considering further changes. Candidate next steps include identifying large
retained Rust standard-library or extendr symbols and evaluating whether
renderer functionality can be separated behind Cargo features. Do not remove
Cargo checksum/provenance metadata, weaken offline verification, or duplicate
shared-core logic merely to reduce the package size.

The source-package vendor NOTE is separate from the installed native library
size and is not addressed by this optimization.
