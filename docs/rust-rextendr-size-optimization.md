# Rust/rextendr installed-size audit

## Scope

This change audits the disposable R/rextendr prototype generated by
`prototypes/rust-rextendr/prepare-r-package.R`. It does not change the
production R package, the shared-core API, or the standalone CLI build.

The generated R package is a separate Cargo package. Therefore, the release
profile in `tools/corrplot-ng/Cargo.toml` is not inherited by the R package.
The audit tested a size-oriented profile in a controlled same-run comparison,
then removed it because it increased the installed artifact on Linux and
macOS. The R integration now retains Cargo's standard release profile.

## Dependency audit

The R prototype's tracked Cargo manifest declares only:

- `extendr-api = 0.9.0`
- the local `corrplot-core` path dependency

The standalone CLI is a separate Cargo package under
`tools/corrplot-ng`; it is not a dependency of the R package. The R package
does not build the CLI executable. CI prints the normal dependency tree and
fails if the standalone CLI package appears in it.

The core crate exports validation plus renderer-neutral output and raster
modules. The R adapter directly uses only `validate_matrix` and
`MatrixKind`. The current audit does not establish that the unused modules
are retained in the linked native library. Rust's linker may discard
unreachable code; feature-gating or splitting the core crate should only be
considered after symbol/section analysis demonstrates a measurable benefit.

## Controlled release-profile experiment

On 2026-10-31, CI compared Cargo's default release profile with a candidate
profile using `opt-level = "z"`, one codegen unit, and debuginfo stripping
(without LTO). Both variants were built and installed on the same runner.

| Platform | Default installed package | Candidate installed package | Change |
| --- | ---: | ---: | ---: |
| Linux | 6,210,450 bytes (5.92 MiB) | 6,642,040 bytes (6.33 MiB) | +431,590 bytes |
| macOS | 2,008,877 bytes (1.92 MiB) | 2,209,927 bytes (2.11 MiB) | +201,050 bytes |
| Windows | 1,183,990 bytes (1.13 MiB) | 1,130,203 bytes (1.08 MiB) | -53,787 bytes |

The candidate profile was rejected: it regressed Linux and macOS, and the
Windows reduction was comparatively small. The generator therefore does not
apply the candidate profile. CI continues to report the installed package,
native library, and Rust static-library artifact sizes for each platform.

These measurements also show that the earlier 6.0 MB / 5.9 MB figures are
approximate historical values, not an exact portable baseline. Package size
depends on OS, toolchain, R version, and target architecture.

## Isolated debug-information stripping experiment

PR #210 completed the platform-specific section and symbol inspection. PR
#212 then ran an isolated experiment against a temporary copy of the
installed shared library. It stripped debug-only data, compared exported
symbols before and after, substituted the copy into the installed package,
and reran the R integration smoke test. The original library was restored
byte-for-byte after the experiment.

| Platform | Original library | Temporary stripped copy | Reduction | Exported symbols | R smoke test |
| --- | ---: | ---: | ---: | ---: | --- |
| Linux (ELF) | 6,207,880 bytes | 2,098,408 bytes | 4,109,472 bytes (66.2%) | 2,443 preserved | PASS |
| macOS (Mach-O) | 1,932,808 bytes | 1,792,600 bytes | 140,208 bytes (7.3%) | 2,376 preserved | PASS |
| Windows (PE/COFF) | 1,164,288 bytes | Not attempted | — | Not verified | Ordinary install/check PASS |

Linux used `objcopy --strip-debug` and compared the dynamic defined-symbol
set. macOS used Apple `strip -S` and compared externally defined symbols.
Windows mutation remains intentionally disabled because the available
tooling has not yet been validated for a reliable debug-only strip and
matching export-table comparison.

These results show that debug information is a major contributor to the
Linux installed-library size, while the macOS reduction is modest. They do
not yet establish that a build-time stripping change is appropriate for
CRAN: the experiment altered only a temporary installed copy and reran the
R integration smoke test, not a full source-package check against a
permanently stripped build. The existing source-package checks still report
one NOTE for Cargo's hidden vendor checksum files. The installed-size INFO
and the source-package NOTE are separate issues.

## Follow-up

## Build-time linker stripping experiment

Merged PR #215 adds an opt-in `CORRPLOT_REXTENDR_STRIP_DEBUG=true` mode to
the disposable package generator. The three-platform offline CI workflow
enables it. Linux passes `-Wl,--strip-debug`; macOS passes Apple's
`-Wl,-S`; Windows deliberately remains unmodified pending validated
PE/COFF tooling. The generator's default remains unchanged when the
environment variable is unset. This is still prototype-only and is not a
production R-package migration.

The full workflow (offline dependency resolution and installation, R smoke
test, source-tarball build, and `R CMD check --as-cran`) passed on all three
platforms in [CI run #41230348952](https://github.com/vsimko/corrplot-ng/actions/runs/41230348952).

| Platform | Installed package | Installed native library | Source tarball | R CMD check |
| --- | ---: | ---: | ---: | --- |
| Linux | 2,112,721 bytes (2.01 MiB) | 2,100,280 bytes (2.00 MiB) | 1,049,181 bytes | 1 NOTE |
| macOS | 1,805,047 bytes (1.72 MiB) | 1,792,600 bytes (1.71 MiB) | 1,048,308 bytes | 1 NOTE |
| Windows | 1,176,796 bytes (1.12 MiB) | 1,164,288 bytes (1.11 MiB) | 1,041,008 bytes | 1 NOTE |

The NOTE is the known R CMD check warning about Cargo's hidden
`.cargo-checksum.json` files retained for offline Cargo integrity. It is
not a linker or runtime failure. Do not remove checksum/provenance metadata
to silence it. The source archive and installed package are separate
measurements.

The temporary-copy experiment from PR #212 was rerun after linker stripping:
Linux changed only from 2,100,280 to 2,098,408 bytes (a further 1,872-byte
reduction), while macOS remained 1,792,600 bytes. This independently
confirms that the build-time linker flags already removed essentially all
debug-only payload available to those tools. Windows was not stripped.

## Follow-up

The measured prototype build-time reduction is now implemented and validated
on Linux/macOS. Do not repeat the experiment or enable Windows stripping
without a validated PE/COFF method. Remaining work is external release
readiness: obtain maintainer/CRAN guidance on the hidden Cargo checksum NOTE
and actual production package acceptance, and complete the human maintainer
time comparison against C++/Rcpp. No production R migration or CRAN
acceptance is claimed.

Do not remove Cargo checksum/provenance metadata, weaken offline
verification, or duplicate shared-core logic to reduce package size.
